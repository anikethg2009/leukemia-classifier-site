# Demo regression check

One fixed input through the demo, expecting one fixed number. It exists so a
future change to preprocessing, the model file, the `1 - output` mapping, the
threshold, or the inference path shows up immediately instead of silently
shifting every score on the page.

## The fixture is synthetic

`cell_a.png` is **drawn, not photographed**: two filled circles and uniform
noise, generated by `make_fixture.py`. It is not a real cell, not from any
dataset, and not an example of the model working.

**0.813 is a checksum, not a result.** It says the inference path is
unchanged. It says nothing about accuracy, and it must never be quoted as a
score on a real cell or used as a demo screenshot.

The real measured numbers live on the page itself and come from the
subject-disjoint test set: 1,882 cells from held-out patients, threshold
0.770, AUC 0.858.

## Expected

| | |
|---|---|
| Input | `test/cell_a.png`, 224x224 PNG |
| sha256 (first 16) | `0dab6a29dcaa1d96` |
| Score shown | **0.813** |
| Verdict shown | **Flagged for review** |
| Console errors | 0 |
| Python reference | P(leukemic) **0.8124375**, onnxruntime CPU, default graph optimisation |
| Tolerance | browser raw score within **±0.0005** of the Python reference |

The weights are float16, so the fourth decimal depends on the runtime's kernels: Python alone gives 0.8124375 or 0.8126213 depending on graph optimisation, and the browser gives 0.8126997.

The score is only meaningful against this exact file. Check the hash first --
a regenerated or re-encoded fixture will give a different number, and that
difference is the fixture changing, not the model.

```
python test/make_fixture.py     # rewrites it and verifies the hash, exit 1 on mismatch
```

## Running it

Serve the repo root and open the page. Then, in the Demo tab:

1. Tick the acknowledgement. The load button and the file input are `disabled`
   in the markup, so this gate holds with JavaScript off too -- neither
   control becomes usable until the box is ticked.
2. Load the model. First load fetches `models/model.onnx` (47,693,953 bytes).
3. Choose `test/cell_a.png`.
4. Read the score.

Expect **0.813**, verdict **Flagged for review**, and the "a score, not a
finding" caveat rendered next to it. The displayed score has three decimals;
to check the tolerance, compare the raw output (P(leukemic) = 1 - P(normal))
against the Python reference above.

## When it fails

A changed score means something in the inference path moved. Check, in order:

- `models/model.onnx` -- byte size and whether it was re-exported or re-quantised
- the BGR channel order and the mean subtraction in `app.js`
- the `1 - output` mapping (class index 1 is `normal`)
- `THRESHOLD` in `app.js`, which is 0.770 and drives both the verdict and the
  meter marker

Re-verify after any change touching `app.js`, the model file, or preprocessing.
